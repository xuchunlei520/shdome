# SHDome 应用市场实现验收矩阵

本文件把开发文档、功能文档中的要求映射到当前代码和验证入口。状态含义：

- `已验证`：已有可重复执行的自动化或真实环境证据。
- `托管 CI 已验证`：已在 GitHub Actions 取得成功结果。
- `生产环境已验证`：已在公网 VPS、真实 DNS 和 Let's Encrypt 环境完成端到端验证。
- `后续阶段`：文档明确列为应用市场完成后的能力，不纳入当前应用市场交付。

## MVP 验收标准

| 编号 | 验收项 | 证据或剩余条件 |
|---|---|---|
| 1 | 一行命令安装并进入菜单 | 公网 VPS 的普通 `ubuntu` 用户已执行 `bash <(curl -fsSL https://k.flowread.cc)`，自动 sudo 后完成下载、摘要校验、原子安装并直接进入菜单；重复安装幂等 |
| 2 | `k`、`k app` 可用 | CLI/发布包冒烟测试 |
| 3 | 至少三个示例应用 | 当前正式目录包含 9 个应用 |
| 4 | 三应用相同容器端口、不同宿主机端口 | 三个真实 `demo-*` 均为容器 80，分别映射 18082/18083/18084；并发争抢仅一个成功 |
| 5 | 默认 IP+端口立即访问 | Uptime Kuma 和三应用均已真实 HTTP 验证 |
| 6 | 三应用分别绑定 HTTPS 域名 | 三应用导入独立证书并通过 `curl --resolve` 验证 |
| 7 | 重启后恢复 | 四个内部容器、隔离 Linux Docker 主机和公网 Ubuntu VPS 整机重启后，应用、HTTP/HTTPS、Docker 及续期 timer 均恢复 |
| 8 | 安装前发现端口冲突 | 顺序冲突和并发争抢均已真实验证 |
| 9 | 健康失败不登记成功 | `demo-bad-health` 无状态登记、无残留容器 |
| 10 | 卸载一应用不影响其他应用 | 删除 `demo-two` 后 one/three HTTPS 继续可用 |
| 11 | 更新失败恢复旧版本 | 无效镜像更新后旧容器、版本状态、配置和数据标记均恢复 |

## 当前不属于应用市场阶段

网站/LDNMP、系统综合管理、网络/内核/安全、测试脚本以及工作区/集群模块仍按 `10–59` 编号段保留，不在主菜单显示，也没有返回虚假成功的占位命令。
