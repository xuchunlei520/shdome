# SHDome 自动镜像源设计

## 1. 目标

SHDome 在部分地区访问 Docker Hub 时可能出现连接超时、限流或下载速度过慢。本功能在不增加普通用户操作步骤的前提下，为所有由 SHDome 发起的镜像拉取提供自动探测、自动选源、失败切换和本地缓存兜底。

普通安装流程保持不变：

```text
选择应用 → 确认一次 → 自动选择镜像来源 → 拉取并安装 → 完成
```

只有实际发生切换时才显示简短提示，不增加镜像源选择页，也不要求普通用户理解 Docker Registry。

## 2. 对 `sh` 项目的参考与调整

`sh` 项目通过 `ipinfo.io/country` 判断地区：中国地区安装 Docker 时使用国内软件源，并向 `/etc/docker/daemon.json` 写入多个 `registry-mirrors` 后重启 Docker。该做法的优点是用户操作少，适合作为自动化入口的参考。

SHDome 不直接复制以下行为：

- 不只依据国家代码判断网络质量。
- 不覆盖用户已有的 `/etc/docker/daemon.json`。
- 不为了单次应用安装自动重启 Docker，避免影响正在运行的容器。
- 不执行未经当前发布包固定和校验的远程换源脚本。
- 不把私有仓库凭据发送给公共镜像代理。

SHDome 第一阶段改用应用层拉取策略：先选择来源并把镜像拉取到本机，再使用原始镜像名称启动 Compose。这样只影响 SHDome 自己的安装任务。

## 3. 分阶段范围

### 3.1 第一阶段：Docker 镜像拉取

本期实现：

- Docker Hub 官方源和少量内置 HTTPS 镜像源的健康探测。
- 根据连接结果、响应时间、历史成功来源自动排序。
- 官方源不可用或明显缓慢时自动使用镜像源。
- 拉取失败时依次尝试其他可信来源。
- 镜像源拉取成功后标记为 Manifest 中的原始镜像名称。
- 所有来源失败时，允许使用本机已有的同名固定版本镜像。
- 接入官方应用、自定义应用、共享 Nginx 和 Certbot。
- 提供状态、测试、自动、仅官方和手工指定镜像源命令。

当前官方目录的九个应用均来自 Docker Hub，因此第一阶段覆盖当前主要场景。

### 3.2 后续阶段

- SHDome 安装和自更新支持 GitHub Release 与可信备用地址自动切换，所有地址继续校验同一 SHA-256。
- Docker/Compose 安装所需的 APT、DNF、YUM、APK 软件包，在系统官方源失败时使用临时镜像配置，不永久覆盖服务器软件源。
- 官方应用 Manifest 增加按架构固定的镜像摘要，由签名官方目录分发。
- 允许管理员显式将选中的 Docker Hub 镜像源事务性合并到 `daemon.json`；默认不开启。
- 为其他公共 Registry 增加独立、显式的可信代理映射；私有 Registry 始终默认直连。

## 4. 来源和镜像引用

第一阶段仅自动代理 Docker Hub：

- `redis:7-alpine` 规范化为 `docker.io/library/redis:7-alpine`。
- `vaultwarden/server:1.37.2-alpine` 规范化为 `docker.io/vaultwarden/server:1.37.2-alpine`。
- `docker.io/...`、`index.docker.io/...` 和 `registry-1.docker.io/...` 视为 Docker Hub。
- 首段包含 `.`、`:` 或等于 `localhost` 的其他镜像视为独立 Registry，默认只直连。

内置候选源保持少量、可替换：

```text
https://docker.1ms.run
https://docker.m.daocloud.io
https://dockerproxy.net
```

候选源只接收不含凭据的 Docker Hub 公共镜像请求。管理员可以用环境变量或管理命令覆盖候选列表；手工地址必须为无用户名、密码、查询参数和片段的 HTTPS Origin。

## 5. 自动决策

### 5.1 探测

探测请求访问每个来源的 `/v2/`，使用短连接超时和总超时。HTTP `200` 或 Registry 常见的 `401` 都表示网络可达。探测结果包含：

- 是否可达。
- TCP/TLS/HTTP 总耗时。
- 最近一次拉取是否成功。
- 连续失败次数和冷却截止时间。

国家代码只作为诊断信息，不直接决定来源。网络探测不可用时，仍可以依据最近成功来源继续拉取。

### 5.2 排序

自动模式按以下顺序选择：

1. 官方 Docker Hub 响应很快时直接优先官方源。
2. 最近成功且未处于冷却期的镜像源。
3. 本次探测中可达的镜像源，按延迟升序。
4. 尚未探测或已经过冷却期的其他候选源。

默认将 500 毫秒以内视为官方源快速响应并直接使用；500 毫秒至 3 秒之间会与候选镜像源比较，只有镜像源至少快约 30% 时才切换；超过 3 秒视为明显缓慢。健康状态缓存 6 小时；同一来源连续失败后进入 30 分钟冷却，避免每次安装重复等待或在来源间抖动。

官方源在 500 毫秒内可达时不额外探测全部镜像源，直接开始拉取；只有官方源响应一般、缓慢、不可达，或管理员执行 `test` 时才探测所有候选，以免网络良好地区的安装平白增加等待时间。

### 5.3 拉取与回退

```text
选择后的首选来源
  ↓ 拉取失败
其余健康镜像源
  ↓ 拉取失败
官方源（尚未尝试时）
  ↓ 拉取失败
本机同名固定版本缓存
  ↓ 不存在
返回完整失败摘要
```

镜像源拉取使用镜像源域名和 Docker Hub 仓库路径。成功后把本地镜像重新标记为原始 Manifest 引用，Compose 不再重复联网拉取。

`latest` 继续被官方和自定义 Manifest 校验拒绝。镜像不存在、架构不支持或认证失败最终必须返回真实错误，不能登记为安装成功。

## 6. 配置和状态

用户策略位于：

```text
/opt/shdome/config/image-sources.json
```

Schema 1：

```json
{
  "schema": 1,
  "mode": "auto",
  "manualMirror": "",
  "mirrors": []
}
```

- `auto`：自动探测和故障转移，默认值。
- `official`：只使用原始镜像引用，仍允许已验证的本地缓存兜底。
- `manual`：优先使用管理员指定的 HTTPS Docker Hub 镜像源，失败后再按自动策略回退。
- `mirrors` 为空时使用发布包内置候选；非空时完整替换内置候选。

运行状态位于：

```text
/opt/shdome/state/image-source-health.json
```

状态记录当前来源、探测延迟、最后成功/失败时间、连续失败次数和最近失败摘要。配置文件权限为 `0640`，状态文件权限为 `0600`；写入使用同目录临时文件和原子替换。

状态同时记录最近成功拉取的原始镜像引用。相同固定版本镜像在 10 分钟内被自定义应用元数据识别和安装流程连续使用时直接复用本地结果，避免创建阶段与 Compose 启动阶段重复联网。

## 7. 命令和交互

普通用户不需要执行任何新命令。管理员入口：

```text
k env mirror status
k env mirror test
k env mirror auto
k env mirror official
k env mirror set <https-origin>
k env mirror reset
```

- `status` 显示当前模式、最近成功来源、时间和错误摘要。
- `test` 立即探测官方源与所有候选源，不改变配置。
- `auto` 恢复自动模式。
- `official` 禁止使用公共镜像源。
- `set` 将指定地址设为手工首选来源。
- `reset` 删除用户策略和健康缓存，恢复发布包默认策略。

切换配置属于管理员操作，需要 root。安装过程中自动选源不增加确认。

## 8. 安全边界

- 默认候选只允许 HTTPS Origin，不允许路径穿越、查询参数、片段、内嵌账号或明文 HTTP。
- 只对公开 Docker Hub 镜像自动改写来源。
- 私有 Registry、带认证的 Registry 和非 Docker Hub Registry 不经过内置公共镜像源。
- 不修改 Docker daemon 配置，不重启 Docker。
- 镜像拉取成功不等于应用安装成功；仍需现有健康检查和状态事务。
- 官方应用继续使用固定 tag，后续通过签名目录增加按架构摘要固定。
- 日志不得输出 Registry 密码、访问令牌或完整认证响应。
- 配置解析采用字段白名单；非法配置回退到安全的 `auto` 默认值并记录警告。

## 9. 模块边界

新增 `src/modules/app_market/image_source.sh`，负责：

- 解析和规范化镜像引用。
- 读取及校验用户策略。
- 探测、排序和状态维护。
- 拉取、镜像源路径转换、原始名称标记及本地缓存回退。
- `k env mirror ...` 命令实现。

现有调用方只调用统一的 `image_source_pull <image>`，不得自行维护另一套镜像源列表：

- `custom.sh`
- `lifecycle.sh`
- `gateway.sh`
- `certificate.sh`

## 10. 验收标准

1. 默认安装交互不增加镜像源问题或确认步骤。
2. 官方源在阈值内可达时优先使用官方源。
3. 官方源不可达或缓慢时，在拉取前自动选择健康镜像源。
4. 首选镜像源拉取失败时自动尝试下一来源。
5. 通过镜像源拉取后，Compose 使用原始 Manifest 镜像名称启动且不重复联网拉取。
6. 全部来源失败但存在本机同名固定版本时可以继续安装，并显示缓存提示。
7. 全部来源失败且无缓存时失败，不写入成功状态。
8. 非 Docker Hub 和私有 Registry 默认不发送到公共镜像源。
9. `official` 模式不访问内置公共镜像源。
10. 手工镜像源拒绝 HTTP、账号密码、查询参数、片段和非法主机名。
11. 用户已有 `/etc/docker/daemon.json` 不被修改，Docker 不因自动选源重启。
12. 应用、自定义应用、Nginx 和 Certbot 均通过统一拉取函数。
13. 镜像源健康状态和最近失败可以通过 `k env mirror status` 查看。
14. Ubuntu、Debian、Rocky、Alma 和 Alpine 的现有安装流程保持兼容。
15. Bash 语法、ShellCheck、单元测试、CLI/辅助函数/发布冒烟测试以及真实 Docker 故障转移测试通过。

## 11. 测试策略

- 单元测试覆盖镜像引用规范化、Docker Hub 判定、镜像源 URL 校验和路径转换。
- Shell 冒烟测试使用 Docker、curl 和时间函数替身验证排序、逐源回退、缓存、状态写入和命令路由。
- 发布测试确认新模块和本文档进入发布包。
- 真实 Docker 测试给缓存镜像增加一个不可达 Registry 标签，验证远端失败后仍能从本地固定版本缓存启动。
- 集成环境使用可控的本地 Registry 代理模拟官方失败、镜像源成功和镜像源返回错误三种路径。
